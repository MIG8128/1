# Goguryeo — Obsidian theme + companion plugin

A glass ("Liquid Glass", iOS/macOS 26–27 style) theme for Obsidian on Windows desktop, iPad and iPhone. The user's colors are Apple system grays, with the accent (green) used only on a few things.

## Files

- `theme.css`: the whole theme. A Style Settings block sits at the top, followed by numbered sections:
  1. Palette
  2. Glass tokens
  3. Text
  4. Tasks
  5. Floating surfaces
  6. Floating panel layout (desktop + iPad: path row, tab row, split screen)
  7. Tabs (sidebar pills, sliding glass thumb)
  8. Auto-hide ribbon
  9. Mobile shared (drawers, the edge-swipe page stage)
  10. iPhone
  11. iPad
  12. Background (Plain / Color / Image behind everything; the note area turns see-through)
  13. Motion
- `manifest.json`: theme manifest. Author is "MIG&Claude (opus5.5)".
- `companion/`: the **Goguryeo Companion** plugin (`main.js` in plain CommonJS with no build step, and `manifest.json`). It does what CSS can't. It mostly sets body classes or CSS variables, which the theme then styles:
  - keeps the left sidebar button out of the hidden ribbon (patches `leftRibbon.containerEl.isShown`)
  - keeps both sidebar buttons in the main tab bar on desktop, ◧ at its start and ◨ at its end, also in full screen where Obsidian would move ◨ into the right sidebar (wraps `workspace.updateFrameless`)
  - desktop touch: swipe from the left edge to open the ribbon (`goguryeo-touch-active`)
  - sliding glass under the active tab of every tab bar (`.goguryeo-tab-thumb`, `goguryeo-glass-thumbs`). Its motion copies the user's Day Planner Pro "GlassSegmented" component: 0.42s `cubic-bezier(0.3,1.3,0.4,1)`, plus a separate `scale: 1.06 1.12` swell held for 320ms.
  - split screen: `goguryeo-split`, `--g-root-top/left/right`, and `.goguryeo-current-pane` / `.goguryeo-last-pane` on the panes
  - split screen with 2+ panes works like Chrome's split view, with any number of splits: a split is a set of panes, each with one page of it (`splitPages`: pane → leaf, `splitOf`: pane → split id; a pane is in one split at most, a pane in none is "loose"); saved as lists of leaf ids per split in `app.saveLocalStorage("goguryeo-split-members")` (the old flat list loads as one split). A new pane joins the split on screen; a split left with one pane ends. Every other tab is a normal tab. Each split is its own joined tab in the row; what's on screen (`syncSplitPages` returns `{solo, split}`) folds everything else away (`applyFold`, body `goguryeo-folded`). A tab dragged from the row onto a pane's edge joins the split on screen there (`tabToEdge`, `splitTabInto`); onto the edge of a lone tab, the two make a new split (`makeSplit`, `previewHalves`). One shared row under row 1 (`renderSharedTabs`, body `goguryeo-shared-tabs`, `.goguryeo-shared-tabs-bar`) shows the pages joined as one tab (`.goguryeo-stab-split` with a `.goguryeo-stab-part` per page, a small dot between pages, the whole joined tab one equal share of the row like any other tab, standing where its first page is) among the normal tabs (`.goguryeo-stab`). What shows follows the focused root leaf (`syncSplitPages`): a split page → every pane on screen, each `selectTab`-ed to its page; a normal tab → it alone, full width (`applySolo`: body `goguryeo-solo`, the other panes/splits at each level get `.goguryeo-solo-off` and fold to nothing but stay in the layout; their fixed ◧ + ⧉ ◨ stay visible). One glass pill (`placeThumb` on the bar) sits on what's on screen; the focused page's name is green. Tabs act like Obsidian's: click = `setActiveLeaf`, × / middle click = detach, right click = `leaf.onOpenTabHeaderMenu`, a normal tab drags with `workspace.onDragLeaf`. The cards' own tab strips are hidden.
  - split screen, moving a pane (iPad Safari style): a small bar at the top middle of each pane (`.goguryeo-pane-grip`, `renderGrips`; shown only while the split is on screen, not solo). Drag it with pointer events (mouse or finger, so the iPad works; no HTML drag and drop) over another pane: within its outer quarter, the nearest edge puts the pane on that side (`createLeafBySplit` beside the target, then every tab moves over); the middle swaps the two panes (a stand-in leaf in each via `createLeafInParent`, since a pane left empty closes itself). A glass box `.goguryeo-pane-drop` shows where it goes; the moved pane gets `.goguryeo-pane-lifted`; Esc cancels. `splitPages` follows the move. Haptic on grab, on each new drop place and on the drop. Dropped on the top tab bar instead (`barDropAt`), or a page part pulled out of the joined tab along the bar (`onPartDown`: a mouse drags at once, a finger holds `CARD_HOLD_MS`; a copy `.goguryeo-stab-ghost` follows), the page leaves the split as a normal tab (`unsplitPage`): its pane's tabs all join the pane beside the drop (the pane closes), the page is placed by its neighbour tab and shown alone (`selectTab` first, or Obsidian keeps the old tab on screen). An empty glass `.goguryeo-stab-slot` grows in where it will stand (`showBarSlot` / `placeBarSlot`, re-placed after each redraw), and the pill follows the changing tabs (`followBar`). The lifted pane only fades its `.view-content`: an opacity or scale on the pane would take its pinned toolbar along.
  - tabs coming and going, exaggerated on purpose (the user asked): in the shared split bar a new tab springs in (`popTab`: flex-grow, scale 0.3 → 1.14 → 1, 560ms; only for a leaf the bar never showed, `sharedSeen`, or the page just unsplit, `dropInTab`) and a closed one swells and shrinks away in its place (`leaveTab`, `is-leaving`, put back after its old neighbour since the redraw re-appends the others); page names in the joined tab do the same (`popPart` / `leavePart`). Obsidian's own tab rows (`watchTabAnimations`, a childList observer on each `.mod-root` strip): a new header's inner pops; a closed one (its leaf gone from `iterateAllLeaves`, not just re-added) is replaced by a copy `.goguryeo-tab-leaving` that shrinks away. Copies are ignored by the observer, or each copy's removal spawned another. All skipped with prefers-reduced-motion.
  - iPhone, one bar at the bottom (design G, `setupPhoneBar`): Obsidian's ≡ becomes ⋯ (`setupPhoneMenu`, click intercepted with `stopPropagation`, not `stopImmediatePropagation`, so the haptics listener still runs) and opens design G's own glass panel (canvas artboards "G · ⋯ open" / "scrolled down"; `openPhoneMenu` / `closePhoneMenu`, `.goguryeo-phone-menu` the width of the bar over a light dim `.goguryeo-phone-menu-bg`, body `goguryeo-phone-menu-open` rings ⋯ green; theme section 10): five tiles ◧ ⧉ ⌕ 📖 ◨ (left sidebar, all tabs, Find in the note (`editor:open-search`), reading view / edit, right sidebar; no ‹ ›, the bar and edge swipe have them), then two-column sections that scroll: "Obsidian" = the ribbon's items unfolded (`leftRibbon.items`, not hidden, `callback(evt)`), then the note's name = its options unfolded: the hidden top row's plugin view actions, then `noteMenuItems(view)`, which builds the same `Menu` Obsidian's own ⋯ opens (its sections, `onPaneMenu(menu, "more-options")`, `onMoreOptionsMenu`, `leaf-menu` event) without showing it and lays its items flat in section order (the "Copy path" / "Open linked view" submenu items get that name in front, from `i18next` `interface.menu.copy-path` / `open-linked-view`; danger items red). A long press on ⋯ still opens Obsidian's ribbon menu. Closes on the dim, Esc, ⋯ again, or a leaf change. **Don't use Obsidian's `Menu` for it: on iPhone that's the stock bottom sheet, which the user rejected ("not the same you've designed").** The capsule is `.view-header-title-container`; the bar is a layer above it, so a tap on the capsule (`capsuleAt`) opens the quick switcher with the path prefilled and selected, like desktop (a folder with a folder note still opens it, `capsuleFolderAt`; changed 2026-10-31, it used to open all tabs). Safari gestures on the capsule (`onPill*`: drag up opens `app.mobileTabSwitcher.show()`, drag sideways calls `workspace.setActiveLeaf` on the neighbouring tab, and the click after a drag is swallowed); and tapping the folded capsule brings the bar back (`app.mobileNavbar.restoreNavigation()`). On iPhone the switcher stays Obsidian's own bottom sheet (`pathCapsule()` returns null).
  - path capsule as an address bar: tapping the path (desktop and iPad: `.view-header-title-container`; iPhone: the folder pill `.view-header-title-parent`) runs `switcher:open` instead of renaming. The `switcher:open` command's callback is wrapped, so Ctrl+O and the palette dock it too: `.goguryeo-omnibox` + `--g-omni-*` on the modal put the search field on the capsule with the list below (theme section 5, which also undoes the iPhone bottom-sheet layout).   - settings tab: every theme option, the same list as Style Settings. It's built from Style Settings' parsed copy of the theme's `@settings` block (`settingsManager.config.goguryeo`) and reads and writes through `settingsManager`, so the two pages always agree and a new option in the block shows up in both. The Background options only show when they apply, and the image gets a picker. The info-text `goguryeo-companion-info` points from Style Settings to this tab, so the tab leaves it out.
  - narrow desktop window: when the note would get narrower than `NOTE_MIN_WIDTH` (480px) beside a sidebar, that side loses its room (`goguryeo-float-left/right`) and the sidebar hides (`autoHide`); it comes back docked once the window is wide enough again (remembered across restarts in `app.saveLocalStorage("goguryeo-auto-hidden")`). Decided only on window width changes, so dragging a sidebar wider never hides it. Meanwhile the window edge brings it out as a peek even with the "Bring out closed sidebars" option off, and ◧/◨ opens it over the note; a click in the note closes it, and when both float, opening one closes the other

Right click on ⧉ keeps Obsidian's menu. Note: `iterateRootLeaves` stops when the callback returns something truthy.
  - desktop trackpad back / forward (two fingers sideways, `onSwipeWheel`): "Trackpad swipe style (this device)" in the companion settings tab, stored per device in `app.saveLocalStorage("goguryeo-swipe-style")`: `smooth` (default, the sliding page over a copy) or `chrome` (the user's laptop found the sliding page heavy, 2026-11-01): a round glass arrow `.goguryeo-swipe-arrow` comes in from the side and fills (`is-armed`) past the go point (`startArrowSwipe` / `setArrowSwipe` / `settleArrowSwipe`); in that style no page copies are taken at all (`getHistoryState` wrapper, `keepWebShot`). After a trackpad swipe lands on a note in editing view the editor gets focus (`focusNote`). In the sliding style `history.go` runs as the slide starts, when the page goes to the same view type (`entry.state.type`; a different type replaces the view and the stage with it, so that one still changes after the slide), and the copy taken for the stage is reused as the left page's history copy (`leavingSnapshot`). In a web viewer the page's picture stays until the page has loaded again (`webPageLoaded`, it reloads when gone back to) and fades off (`is-lifting`).

### Sandbox gotchas (verified 2026-10-24)

- The settings window is its own DevTools page, and its title starts with "설정" (the sandbox UI is Korean). In it, `app` is undefined; use `window.opener.app`. Example: `node sandbox/cdp.mjs --page "설정" eval 'window.opener.app.customCss.theme'`. Open it with `app.setting.open()` and close it with `app.setting.close()`.
- Reload the plugin with `app.plugins.disablePlugin(id)` and then `enablePlugin(id)`.
- To close the sandbox, kill only the processes whose command line contains the full `--user-data-dir=...\Goguryeo\sandbox\app-data`. Don't match on the word "sandbox" alone: Chromium's flags (`--service-sandbox-type`) contain it in the user's Obsidian processes too.
- First start: if a trust dialog appears, click "작성자를 신뢰하고 플러그인 사용하기" over DevTools: `[...document.querySelectorAll(".modal button")].find((b) => b.textContent.includes("신뢰"))?.click()`. In this setup it didn't appear, and the plugin loaded right away.
- **Never minimize the sandbox window.** A minimized window reports `document.visibilityState === "hidden"`, so `requestAnimationFrame` stops and the tab thumbs and motion never update. Restoring it also takes focus. The launch flags keep it rendering when other windows cover it. Without them, a covered window counts as hidden too.
- A new window takes focus, and `blur()` doesn't release it. `nofocus` (`setFocusable(false)`) drops the focus, and the window keeps rendering.
- Electron has no `Browser.getWindowForTarget`, so `bounds` sizes the window through `require("@electron/remote").getCurrentWindow()`.
- Phone and tablet layout: `app.emulateMobile(true)` reloads the app as a phone (`is-mobile is-phone`). Set the size with `bounds` (e.g. 430×900 for a phone). It persists across restarts, so always end with `app.emulateMobile(false)`. It's still Chromium (see the WebKit gotcha below).
- Pass JS to `node sandbox/cdp.mjs` from Bash in single quotes. PowerShell 5.1 strips the inner double quotes when calling native programs.

## Obsidian 1.14.5 gotchas (all verified)

- The left ribbon only has the class `mod-primary`, never `mod-left`. Sidebars and the sidebar buttons have both classes.
- `body` has `contain: strict`, so `position: fixed` elements still have an offsetParent, and `isShown()` is true for them.
- `.workspace-leaf` has `contain: strict !important`. A fixed element inside a pane is positioned relative to that pane. Split mode relaxes this to `contain: size !important`. Use plain `size`: a value Safari rejects would bring back Obsidian's strict.
- Obsidian gives sidebar `.workspace-tabs` `width: 100%`. Use `width: auto` when adding margins.
- The tab close button has `inset-inline-end: 0`. Cancel it if you set `left`, or the button covers the whole tab.
- Obsidian rebuilds a tab bar's children and drops foreign elements, so the plugin remembers each bar's last thumb position.
- When Obsidian moves the sidebar toggle, it leaves an animating clone. Compare against `app.workspace.leftSidebarToggleButtonEl`.
- iPhone: Obsidian hides the bars on scroll with a transform on `.view-header`. The theme slides it with `top` instead, because a transform would drag the fixed note-name pill along with it.
- iPhone: the theme keeps Obsidian's `.view-header` (height 0, children hidden) because it holds the capsule (`.view-header-title-container`, `position: fixed` at the bottom). The note's top room comes from `--view-top-spacing(-markdown)`, which Obsidian computes on `body` from `--view-header-height`; the theme redefines both on `.workspace-leaf`. Obsidian's ≡ opens its menu from a plain `click` listener on its `.clickable-icon` span (`onRibbonMenuClick`, or a quick ribbon action if one is set in `mobileQuickRibbonItem`).
- **The preview is Chromium, and the real iPhone and iPad run Safari (WebKit).** Safari clips `position: fixed` children with any ancestor's `overflow: hidden`, especially a rounded one. Chrome doesn't, so the preview can't show this. That's why the iPad toolbar vanished in card mode: in split mode, `.workspace-tabs`, `.workspace-tab-container`, `.workspace-leaf` and `.workspace-leaf-content` are now `overflow: visible`, and `.view-content` clips itself with `clip-path`. Never put a clipping box around fixed UI.
- On iPhone and iPad, plugin (`main.js`) changes only load after Obsidian is fully closed and reopened; the theme CSS applies as soon as it syncs. Tell the user this whenever a change is in the plugin.
- iPhone: Obsidian brings the bars back by itself when the note is scrolled to the top. To test the folded capsule, scroll the note down first (set `scrollTop` and dispatch `scroll` events), don't just call `hideNavigation()`.
- Obsidian's mobile API: `app.mobileNavbar` (`hideNavigation`, `restoreNavigation`, `tabButtonEl`), `app.mobileTabSwitcher` (`show`, `hide`, `isVisible`), `leaf.history` (`backHistory`, `forwardHistory`, `go(n)`). `WorkspaceLeaf.prototype.getHistoryState` runs just before a leaf leaves a page.
- iPhone sidebars: the drawers are `position: fixed` and slide in with inline transforms (200ms). Obsidian's own **"Sliding sidebars"** option (Settings → Appearance, iPhone only; config `slidingSidebar`, on by default and on in this vault) also slides `rootSplit.containerEl` and `mobileNavbar.containerEl` by the drawer width (84vw), which pushes the whole tab aside. Body-level fixed elements such as ◨ don't move, so the theme fades them while `.workspace` has `is-left-sidedock-open` / `is-right-sidedock-open`.
- Obsidian paints `.workspace-drawer-inner` and `.workspace-drawer-active-tab-container` solid, and fades lists into that color with `::after` gradients; the theme clears both so the drawer glass (`--glass-sidebar`, the Sidebar opacity setting) shows.
- Mobile keyboard: `body.is-mobile .app-container` gets `max-height: calc(100vh - var(--keyboard-height))`; the body stays full height. `.app-container` is not positioned, so its absolute pseudo-elements are placed against the body.
- iPad: the note area has `padding-top` for the status bar. The plugin adds it to `--g-root-top`.
- Settings opens in its own window (a separate DevTools target, url about:blank), so a `shot` of the main window doesn't show it; capture that target instead (`--page "설정"` in the sandbox).
- Platform: Obsidian's mobile app puts `is-ios` or `is-android` on `<body>` (its own CSS uses them); in JS use `Platform.isIosApp` / `Platform.isAndroidApp`. `require("obsidian")` doesn't work from the DevTools console, so to test code that reads `Platform`, rebuild the method from its source with a stand-in (`new Function("Platform", ...)`).
- Every Obsidian dropdown in settings has a second one-option `<select>` beside it (Obsidian's own); don't count it as a duplicate option.
- You can extract Obsidian's own CSS and JS from `%APPDATA%\obsidian\obsidian-1.14.5.asar` (it's a plain asar file) to look up class names.

## User preferences and decisions

- Write in English. The user writes in short sentences and likes seeing screenshots and checks.
- **iPhone UI needs haptics.** Every touch control or gesture the companion adds must call `this.haptic()`: on a tap, and when a gesture crosses its go point. The user insisted ("remember!").
- iPhone and iPad gestures follow iOS Safari: edge swipe with the other page underneath, a name pill that folds into a capsule on scroll, and drag the pill up or sideways.
- When the user describes a change exactly, building it directly is fine without a design-canvas mockup first; check it with screenshots.
- **No gradient backgrounds.** The glass comes from light, blur and content scrolling underneath, or the user's own background (section 12).
- **Flat glass:** no brighter top edge, no top sheen, no top-to-bottom gradients on controls.
- **Windows window buttons (— ▢ ✕) stay native** in the top-right corner, and the right sidebar starts below them. The user rejected moving or restyling them twice.
- **The tab row never hides** on desktop and iPad, not even with one tab or only the empty new tab (the user rejected Safari's one-tab hiding, 2026-10-30).
- Desktop: the ribbon auto-hides. The tab row stretches across the full width under a path row (iPad Safari style). The sidebar tab pills span the full sidebar width. Split screen uses one shared toolbar with panes as cards and a green edge on the current pane.
- iPhone (design G, chosen 2026-10-31): no top row, one bar at the bottom: `( ‹ ) ( folder › note name ) ( ⋯ )`, round glass. The capsule shows only the note's folder (for a folder note, the folder around it; the user uses the Folder notes plugin and many folders); a long folder takes at most 40% and both parts shorten with "…". Everything else (forward, reading view, note options, sidebars, all tabs, find in the note, Obsidian's menu) is in ⋯. The tab overview has no Search files pill (removed 2026-10-31: the capsule tap already opens the quick switcher), only Obsidian's [+] [N tabs] [Done] row. Tapping the capsule (name or folder) opens the quick switcher with the path selected, like desktop (a folder with a folder note opens that note). Scrolling down folds the bar into a small capsule with only the name, as wide as the name (`--g-capsule-name-w`, measured in `setupNameCapsule`; 80–260px). Like Safari's address bar, the name pill also takes gestures (companion): drag up to open the tab overview (`app.mobileTabSwitcher.show()`), or sideways to go to the tab beside it (left goes to the next tab, right to the previous). On the last tab, dragging left opens a new tab, like Safari.
- The user's other plugins are Day Planner Pro (their own plugin, which has the glass tokens), Style Settings, Typewriter Scrolling, Dayloom and others. Minimal Theme Settings is turned off.
